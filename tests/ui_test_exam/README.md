# AsterFlow 前端缺陷盲测考试

本目录用于验收 **`dsh-agent-team-ui-testing` 插件自身**的 GUI 调试与测试能力。靶机是一份可离线运行的业务后台 HTML，内含 **20 处预设的前端样式、视觉、状态和动画缺陷**。考生需要通过插件发现、复现、取证并报告问题。**不得通过其他自动化工具代替插件完成考试。**

## 目录与访问边界

```text
AsterFlow_UI_Test_Exam/
├── README.md                                  # 考试规则：考生可读
├── target/
│   └── AsterFlow_Workspace.html               # 唯一允许打开/测试的靶机
└── _examiner_only/
    └── AsterFlow_Exam_Answers.html            # 考官试卷及标准答案：考生禁止访问
```

> **考官须知：** `_examiner_only/` 只是目录隔离，**不是安全隔离或加密**。正式盲测时，只向被测 Agent 提供此 README 与 `target/AsterFlow_Workspace.html`（或仅提供指向靶机的浏览器会话），将考官文件保留在它无法访问的目录。不要把整个 ZIP 交给被测 Agent 后仅依靠提示词保密。

## 必须遵守的测试约束

1. **唯一执行通道：** 仅通过已经安装并启用的 `dsh-agent-team-ui-testing` 插件**实际提供**的工具、能力、UI 和后台浏览器会话操作靶机；先发现真实可用能力，不得假定某个工具名称或接口必然存在。
2. **禁止外部工具或库：** 不得另行安装、导入、编写或调用 Playwright、Puppeteer、Selenium、Cypress、Browser Use、Chrome DevTools MCP、第三方自动化插件、截图/图像分析库或视频处理库来完成考试；也不得用独立 Node.js/Python/CLI 脚本、`curl`、系统 GUI 自动化、浏览器开发者工具等绕过本插件。**插件内部已经集成的依赖可以由插件正常调用，但考生不得绕过插件直接使用这些依赖。**
3. **禁止偷看答案：** 不读取、打开、搜索、解析或通过任何方式访问 `_examiner_only/` 中的文件；不搜索既往考试结论、标准答案或预置缺陷清单。
4. **禁止源码作弊：** 不通过文件系统直接读取/搜索靶机 HTML、CSS 或 JavaScript 源码以提取预设缺陷或答案。允许通过**插件公开的 T1/T2 能力**在运行时检查页面 DOM、CSSOM、可访问性状态、网络事件和动画对象，但必须将这些发现与页面实际行为或渲染结果对应起来。
5. **不得改动考场：** 不编辑靶机文件，不修改页面脚本、样式、DOM 来掩盖缺陷，不直接伪造测试记录。允许通过插件执行正常 UI 操作、选择元素、读取可见与运行时状态、截图、连续帧记录，以及必要的受控测试动作；结束后保持或恢复页面可用状态。
6. **不准偷偷降级：** 如果插件缺少某项能力，需明确标记“当前插件不支持 / 证据不足”，不能换外部自动化方案补测，也不能把猜测写成已验证结果。
7. **无焦点与共享会话约束：** 测试应在插件管理的后台浏览器工作区完成，不抢占宿主机前台焦点；保留独立浏览器 viewport，不把 DSH 侧栏的缩放尺寸视为网页分辨率。如启用 Agent Team，应在共享会话中管理标签页与控制权，避免同一标签页写操作相互冲突。

## 建议考试流程

1. 使用插件打开 `target/AsterFlow_Workspace.html`。优先使用 **1365 × 900** 的真实浏览器 viewport；可额外回归 **1024 × 768**。Viewer 可以任意缩放，但测试以真实 viewport 为准。
2. 像检查真实业务后台一样浏览页面：顶部导航、侧栏、指标卡、图表、状态控件、弹出层、表单和交互反馈等。靶机**不会标注题号、难度、T1/T2/T3/T4 或混合题**。
3. 选择插件当前最适合的可用能力完成检查：程序化接口、结构化 GUI、静态画面、动态时序，以及它们的组合。发现问题后用第二种可用证据交叉验证，避免只凭单次推测。
4. 动画类问题尽量记录带时间戳的连续观测；循环动画至少看**两个完整周期**，一次性进出场动画至少覆盖一个完整生命周期。记录采样限制，不把 Viewer 播放掉帧直接等同于页面卡顿。
5. 逐条形成缺陷报告。目标是报告 **20 项真实缺陷**，但不能为了凑数制造虚假缺陷；未找到的如实说明。
6. 提交报告后由考官单独打开 `_examiner_only/AsterFlow_Exam_Answers.html` 评分。该文件含试题和标准答案，并不属于考生可访问材料。

## 必须提交的测试报告

对每条缺陷至少记录：

| 字段 | 填写要求 |
| --- | --- |
| 编号 | 自行编号 F-01、F-02……，不预设与标准答案的顺序一致 |
| 页面位置 | 所在模块、组件或界面状态 |
| 复现步骤 | 使用**插件工具**完成的可重复步骤，包括必要的触发操作 |
| 测试环境 | 浏览器 / viewport / Viewer 缩放（如有关） |
| 实际结果 | 客观观察到的样式、数值、状态或时间变化 |
| 预期结果 | 可依据的设计令牌、语义状态、布局规律、交互一致性或可用性原则 |
| 证据 | 插件输出的 DOM/ARIA/CSSOM 信息、截图、画面区域、网络日志或带时间戳的帧序列；引用证据文件/标识 |
| 能力路径 | 实际使用的插件能力及必要的跨能力验证过程 |
| 修复建议 | 最小可行修复思路；**不直接修改靶机** |
| 结论 | 已证实 / 待复核 / 插件暂不支持，并说明不确定性 |

**验收重点：** 缺陷定位正确、证据能独立复核、推断过程没有绕开插件、动态缺陷有时间维度证据、共享浏览器/Viewer 约束得到遵守。考官参考卷满分 100 分，每题 5 分（定位 2 分、证据 2 分、建议修复 1 分）。
