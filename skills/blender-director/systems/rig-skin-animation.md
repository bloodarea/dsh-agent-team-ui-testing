# 骨骼、蒙皮与动画

```json
{"id":"rig-skin-animation","version":"1.0.0","requiredOps":[]}
```

## 输入

阶段 brief、规范化关节/动作规格片段与 specRef、已绑定对象 ID、变形网格与拓扑检查、rest/pose 空间、前向与上轴、关节稳定 ID、帧率、动作窗口、实际能力/op 版本和交付格式。缺侧视的厚度、未知关节结构与轴向作为候选，不能自动确认。

## 操作与边界

只有 brief 需要绑定或动画才使本阶段成为发布门槛。先规划 rest pose、骨层级、权重归一化和典型动作，再评估眼口、肩肘、髋膝等变形区的拓扑是否支持要求。角色服装与刚性附件分别声明绑定方式；道具铰链明确转轴与枢轴。

当前 8 个受控 op 不提供建骨、权重、关键帧和动画采样写入，`requiredOps=[]` 仅提供规划入口。刚性 `object.parent` 和静态 `object.transform` 不能等同蒙皮/关键帧。把专业能力缺口、无效骨 ID 或不可读动作数据列 blocker，保留静态网格、骨架方案和时间窗；禁止 Python、工程文本块或任意脚本回退。仅在能力目录声明等效可用路径后重做 plan，写入仍需 Tools 与租约。

## 输出

输出 `version=1.0.0`、briefId/stageId/specRef、boundObjectIds、空的执行 proposal.ops、骨层级/权重/动作方案、checks、dependencies 和 blockers。动作结果需要已验证的时间戳/帧号，不把播放预览或静帧当成完整动作证据。

## 下一阶段门槛

| 指标 | 单位 | 来源与容差 | 所需证据 |
| --- | --- | --- | --- |

缺专业 op 或过程证据的检查为 unknown，阻塞承诺的绑定/动画交付。变形失败先区分结构、拓扑或权重问题，回到最早失效阶段，修复后重新采样受影响动作窗口。静态交付可由用户明确排除该阶段，不能伪造动画通过。
